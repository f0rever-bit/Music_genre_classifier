## Hamburger Menu для мобільних Navbar

### Що робимо
Додаємо мобільне меню в `Navbar.jsx`, щоб на екранах < 768px ( breakpoint `md`) користувач мав доступ до Dashboard, Recommendations, Admin.

### Зміни

**1. `frontend/src/components/Navbar.jsx`** — єдиний файл що змінюється:

- Імпортуємо `List` та `X` з `@phosphor-icons/react` (hamburger + close іконки — вже є `X` в UI, але додаємо для Navbar)
- Додаємо `const [mobileOpen, setMobileOpen] = useState(false)` стан
- Додаємо `useEffect` для закриття меню при зміні маршруту (`location.pathname`) та при resize до `md+`
- Перед `<nav>` додаємо hamburger кнопку: `<button className="md:hidden ..."><List /></button>`
- Замість `hidden md:flex` на `<nav>` — залишаємо `hidden md:flex` (десктоп навігация не змінюється)
- Після десктопного `<nav>` додаємо мобільне меню — повноекранний overlay (`fixed inset-0 top-16 z-30 bg-background/95 backdrop-blur`) з анімацією fade-in, що містить:
  - NavLink для Dashboard
  - NavLink для Recommendations  
  - NavLink для Admin (якщо `user?.is_superuser`)
  - Separator
  - Upload options (From File, Bulk, Spotify)
  - Separator
  - Settings + Logout
- Кожен клик по посиланню закриває меню (`setMobileOpen(false)`)

**2. `frontend/src/i18n/locales/en.json` + `uk.json`** — додаємо ключ `nav.menu` ("Menu" / "Меню") для `aria-label` hamburger кнопки

### Що НЕ робимо
- Не чіпаємо десктопний layout
- Не додаємо нові CSS-класи (використовуємо існуючі Tailwind + анімації з `index.css`)
- Не додаємо нові залежності

### Перевірка
- `cd frontend && npm run build` — 0 помилок
- Візуально: на екранах < 768px hamburger з'являється, меню відкривається/закривається, всі посилання працюють
